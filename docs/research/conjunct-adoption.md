# Composition platform research and integration plan

**Inspected:** 2026-10-04. **Evidence:** complete reads of both development
branches, current upstream source through GitHub CLI, primary technical
sources, current Frameshift consumers, and the bounded test run below.
**Decision:** use Conjunct's existing deterministic kernel and portable guide;
define and qualify the Frameshift profile before switching semantic authority.
Transactional services remain on hold. No new hardware, installed product,
financial operation or complete Conjunct conformance was qualified here.

## Findings and recommendation

The composition workbench can now be planned against real producer exports.
Conjunct has a pure Rust kernel, supervised Elixir process binding, browser
WASM binding, validated data views and an offline instruction renderer. It is
no longer accurately described as specifications without runtime code. These
exports are unreleased, however, and none is installed or qualified by the
Frameshift application. Its semantic vectors also still await independent
review. Code availability, distribution, semantic conformance, consumer
qualification and physical validation are distinct gates.

Keep the existing Phoenix/Ash/phoenix-assets/Svelte product host. Consume the
same upstream semantic kernel through the Elixir port and browser worker;
do not extract another generic Gleam engine into Frameshift or rebuild
Conjunct's comparison, check aggregation, catalog projection or procedures in
Svelte. Preserve the existing v1 codecs, identities and thirteen-stage preview
for replay, migration and frame-rule regression. The native app, Zig artwork
renderer, Frame Protocol, pairing and receiver recovery retain their owners.

The first implementation target is a complete **synthetic software fixture**,
with compatible, incompatible and unknown variants, that produces an exact
composition, purpose-bound reports, procedure, parts list and self-contained
guide. It proves software behavior, not a buildable frame. Run the three sourced
Paper/Photo/Pixel candidates as unknown/refusal cases alongside it. A real
candidate cannot become compatible by dropping its missing controller, power,
thermal, connector or revision obligations. A measured physical configuration
is a later, independently evidenced artifact.

The [specification delivery plan](../architecture/implementation-plan.md#composition-specification-delivery)
names the owning files, ordering and acceptance for each slice. Research is
sufficient to start that specification work and bounded consumer experiments;
it does not authorize switching the current compiler or admitting an actual
frame. Source-permitted manual geometry makes the first guide independent of
CAD acquisition, operator generations, model inference and checkout.

## Conjunct kernel and distribution

The [trusted registry](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/distribution/src/registry.rs)
installs `cj/core/0.2`, `cj/geometry/0.1`, `cj/packaging/0.1` and
`cj/procedures/0.1`. It derives an unreleased semantic contract identity from
normative documents, schema digests and algorithm records:
`urn:conjunct:contract:unreleased:<digest>`. A profile name or package version
alone cannot identify the semantics. Requests and product packs cannot install
new contracts into this trusted registry.

The [portable protocol](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/docs/specs/cj09/kernel-protocol.md)
uses `cj/kernel/0.1`; transport/ABI identities are separate. The seven domain
operations are `normalize_requirement_set`, `compile_composition`,
`compare_compositions`, `plan_procedure`, `plan_packaging`,
`validate_product_pack` and `project_catalog`. Use the actual request schemas
and discovery, including CJ.09 and the current domain/geometry annexes. The
older CJ.01–CJ.08 prose alone is not an encoder specification.

The [Elixir binding](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/bindings/elixir/conjunct_kernel/README.md)
is a passive library. The host starts `Conjunct.Kernel.Port` under its own
supervisor with an executable path/digest, deadline and bounded queue.
`Conjunct.Kernel.describe/2`, `create/3`, `load/3`, `call/3` and `destroy/2`
accept explicit server/context and exact bytes. The transport verifies the
executable, spawns directly with an empty environment and permits one
outstanding request. Deadline/process/framing loss invalidates the instance's
contexts; numeric ID reuse cannot revive an old context. There is no automatic
replay. Restarting a worker and explicitly reloading immutable inputs is
separate from admitting or retrying an effect.

The [TypeScript binding](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/bindings/typescript/conjunct-kernel/README.md)
provides `RawKernel` and `WorkerKernel` over `cj/wasm-abi/1`. Raw calls are
single-flight; the worker owns cancellation/deadline termination and context
generations. Qualify this staged distribution in Frameshift's actual browsers
and TypeScript 6.0.3 build. Upstream development on TypeScript 7 does not prove
that emitted declarations work with this consumer. Kernel/guide npm packages
are private and Rust packages are unpublished. A source archive, executable,
WASM, declarations, license inventory and exact digests need a reproducible
consumer distribution contract; release/signing claims remain separate.

Transport success is not semantic success. `{:ok, response}` means a reply
arrived; its `outcome` can be completed, refused or incomplete. A completed
physical CheckReport can be compatible, incompatible or unknown. A timeout is
a transport failure, not a failed physical rule. UI and server must preserve
all three layers and show stale worker contexts as unavailable.

The Frameshift product profile is data: ProductDefinition, PartRevision,
RuleSet, evidence/assessments and ProductPack under installed semantics. It
cannot register an arbitrary new kernel profile/operator. Exact operating
scopes distinguish continuous, surge and storage ratings; matching units alone
cannot establish comparable conditions. Unsupported generic computations need
a producer profile extension and a refusing consumer fixture.

The [data binding](https://github.com/futhr/conjunct/tree/f6609c5e4c2188626f5e1f345446fec04e78d6c9/bindings/elixir/conjunct_data)
validates original bytes before producing typed views. Its UTF-8/JCS schemas
and limits do not authorize loosening Frameshift v1's 256 KiB/depth-16/ASCII
contract. [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) canonicalization,
exact string rationals and producer artifact domains require an explicit
successor mapping. Preserve original bytes and old IDs; test Unicode,
duplicate keys, ordering, overflow and unit/kind conversion. Missing,
conflicting and unrepresentable mandatory data must survive or refuse.

## Frame rules and migration coverage

The retained preview evaluates thirteen ordered stages. Neither a generic
profile label nor a generic `sum_le` predicate proves all of them are covered.
Map each obligation to a producer-supported rule, assessment or operation;
where no faithful expression exists, retain an explicit unavailable result and
an upstream requirement with a reproducing fixture. Do not omit the rule or
run a hidden second generic compiler after a nominally successful kernel call.

| Existing stage | Mapping that the specification slice must freeze |
| --- | --- |
| Graph checks | Occurrence paths, repeated subassemblies, reachability, identity and conserved counts |
| Geometry | Complete envelope/clearance, exact placements, source/feature bindings and coordinate conversion |
| Viewing | Active area, mat/opening and frame-specific viewing requirements; mesh appearance is not optical evidence |
| Power interfaces | Exact voltage/interface compatibility, polarity and revision-dependent limits |
| Power loads | Worst-case loads, branch/aggregate capacity, simultaneous operations and source conditions |
| Power contracts | Actual continuously powered versus bistable behavior, refresh/storage/activation obligations |
| Thermal | Installation-specific dissipation, rated conditions and required physical assessments |
| Mounting | Weight, support, keep-outs, access, fasteners and sourced required observations |
| Signals | Panel/controller signal/timing/raster capability and exact revision |
| Signal routes | Complete paths, bridges, connectors and no assumed pin/interface interchangeability |
| Operation | Persistence, last-valid artwork, interrupted refresh and supported recovery assumptions |
| Artifacts | Host-rendered still-image formats, byte/pixel bounds and frame raster/storage obligations |
| Completeness | Required missing/conflicting facts stay unknown; a caller cannot weaken the selected frame profile |

Generic predicates can cover some checks but do not automatically supply DC
flow, timing, storage or physical assessments. Product-owned input derivation
must be explicit, bounded and independently checked; reusable semantics belong
upstream. Freeze an obligation-to-fixture matrix before implementation, with
positive, violated and missing/conflicting variants for every mandatory rule.
Keep the v1 oracle independent of the new adapter to detect erased obligations.

Positive test-purpose inputs use declared synthetic assumptions, not fabricated
physical measurement records. Their reports remain bound to that purpose;
actual-build admission still requires the applicable physical evidence.

The existing three catalog candidates lack complete validated installed
configurations. Preserve their source digests and unresolved facts. A synthetic
compatible composition has synthetic claims/assessments and never enters the
validated hardware list. Migration records old/new IDs, semantic changes and
read/write/execute support independently; it never rehashes accepted rows in
place. Because the product is unreleased, any schema changes edit the original
migration, using `_create_` for tables and `_install_` for extensions.

## Procedures, geometry and accessible output

The [guide renderer](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/frontend/guide/README.md)
consumes a ProcedurePlan, its report, the physical composition report,
DocShell projection and detached status. It produces self-contained HTML
without scripts or network assets. A compatible procedure cannot override an
incompatible/unknown physical composition. Missing reviewed essential wording
blocks execution; text/print/offline views retain semantic IDs, quantities,
conditions, warnings and evidence instead of generating plausible instructions.
Browser-local progress records are explicitly unadmitted observations.
Reconnection must not turn them into accepted work or effects automatically.

DocShell supplies actual `DocShell.Generate.Collection.new/1`, `digest/1`,
`load/2`, `load_many/2` and projection boundaries; the Frameshift consumer
supplies exact permitted collection, procedure, locale and authorized fields.
Do not create a parallel documentation store. The first software fixture can
use an explicitly reviewed synthetic collection. Real product content,
translations and human accessibility trials remain separate qualification.

The selected [STEP cohort](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/adapters/step/cohort.json)
is much narrower than general CAD support: Linux/arm64, Rust 1.97.1, OCCT
7.9.3, pinned opencascade-rs, single-file ASCII AP214 planar B-rep with named
nested assemblies/shared products and explicit mm/m, Y/Z up. Its delivery
profile is `cj/step-planar-assembly/0.1`. It excludes AP242, curved geometry,
PMI, colors/materials, external files, archives, manufacturer geometry,
engineering accuracy and canonical rational feature placement. Activation is
explicitly unqualified; native licensing/source/relinking closure and signing
remain open. Do not advertise the broader `cj/cad-step/0.2` requirement as this
implementation's supported capability.

[glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)
uses metres and a right-handed +Y-up convention. Frame coordinates and
source units still need explicit transforms, handedness, tolerances, stable
feature mapping and a loss report. A delivery mesh alone cannot authorize
clearance, torque or fit. Manual exact geometry supports the first slice;
manufacturer CAD and engineering conversion qualify independently.

## Adaptive admission and formal evidence

Refpath's installed `Refpath.Definitions.ApplicationAdmissions` already exposes
`admit/2`, `current/2`, `restoration/2`, `pin/2` and `source/3`; `HotReload`
provides public scoped wrappers. Durable application-scoped heads, verified
artifact closure, predecessor/fence/receipt semantics and trusted host
qualification exist. The old description of a solely volatile generation
surface, requiring P1 from scratch, is obsolete. Their existence does not
prove the two-operator Conjunct join at Frameshift's installed revision.

Conjunct's [current seam audit](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/docs/research/implementation-seam-audit-2026-10-03.md)
separates its selected cohort from a prospective Refpath
`Artifacts.with_review_projections/3` transaction. The prospective join checks
review authority through commit, but the complete producer Credo gate failed
with 33 findings; that snapshot was not selected. This export is absent from
Frameshift's installed source. Repeated unlocked review reads cannot establish
atomic admission. Qualify a producer-owned transaction/fence across review
withdrawal and head commit before the dependent operator feature is enabled;
do not add a consumer lock or shadow active-generation registry.

ExMaude's `ExMaude.Verification.SearchRun.run/3` now returns typed termination
and bound model/query/executable/parser/session/limits/output/trace evidence.
Its outcomes distinguish exhausted search space, completed declared bound,
depth truncation, solution limit, timeout, output truncation, worker loss and
parser error. The source includes isolated-worker cleanup, including caller
loss. Do not propose these as wholly missing APIs. Conjunct's
[formal join](https://github.com/futhr/conjunct/blob/f6609c5e4c2188626f5e1f345446fec04e78d6c9/conformance/formal/README.md)
reports six cases for screw reach and sensor capacity, including broken-rule
witness replay. Typed cancellation receipts, state-count limits and complete
frame predicate/trace coverage remain open. An empty bounded search is not a
proof, and those two models are not the whole physical compiler.

Independent composition/guide work need not wait for an operator host or formal
claim. When a profile requires a formal result, missing evidence blocks that
claim. Freeze the formal fixture/model vocabulary against the exact frame
profile rather than extending a second generic model catalog in Frameshift.

## Optional services and models

The build proposal's lead assembler, marketplace fee, regional seller model,
PSP, shipping aggregator and legal assumptions are not selected requirements.
Technical saga/idempotency/care concepts are retained in BC-01–BC-10. Any later
resumption needs explicit jurisdiction/counterparty/terms, public capability
exports, exact provider environment, credentialed refusal/reconciliation tests
and qualified financial receipts. It is not part of the first implementation.

Rivure's ExternalCommitment preview/invoice/finalize/cancel/refund boundary
already exists. Its inspected amount model currently requires a currency
exponent of two, and its opt-in account integration is Connect v1. These are
capability limits; neither generic multi-currency support nor automatic Connect
v2 compatibility follows from method names. Refpath delivers a command, Rivure
owns provider mutation/retry and financial truth, and Frameshift owns domain
receipts. Cancellation/refund must reconcile the actual original tender and
unknown external outcomes rather than inventing cash compensation.

No new model is selected. A Banking77 result or a model family name does not
qualify frame selection, source extraction, physical policy or company
operations. Optional text interpretation needs a task-specific held-out corpus,
confidence/refusal thresholds, deterministic schema/rule validation, privacy and
measured budgets. Generated text may propose facts; reviewed evidence and
current scoped policy remain authoritative.

## Plan review and decision limits

The plan was revised against three concrete failure modes: obsolete claims
that producer APIs were wholly missing; an apparently successful migration
that erased frame obligations; and a useful guide falsely presented as physical
or current-authority approval. The final sequence separates source discovery,
loss-refusing migration, rule coverage, offline output, authenticated writes,
operator/formal evidence and exact hardware qualification.

Proceed with specification slices S1–S4 and the synthetic consumer experiment
in the linked plan. Freeze the actual contract/schema/diagnostic fixtures before
writing the adapter. Keep S5's server mutations, S6's operator/formal claims and
S7's physical claims gated by their own prerequisites. A failed required rule,
unsupported export, changed cohort or unmapped mandatory fact invalidates the
affected slice; it does not halt independent native work or justify a duplicate
producer implementation. No research-only PASS table substitutes for these
observable acceptance gates.
